# 0.2.3 美术统一与开发依赖整理

## 本轮计划

1. 所有卡面统一接近 B：柔和的金属体积、干净的色彩和简洁背景。
2. 所有悬浮武器统一接近 C：清晰轮廓、必要的几何金属高光、真实透明背景。卡面与悬浮图沿用同一武器的造型和配色。
3. 本模组的状态图标统一接近 D：少量纸片色块，缩小后仍能辨识。
4. 核查本地与工坊 RitsuLib 的用途及版本，防止开发部署反复创建本地运行副本。

## 逐项改动

- 替换 15 张卡面：包含所有 12 件君王武器、趁手兵器、水晶小刀和子弹。卡面在 `MoreWeaponsRegentExtend/images/cards/`。
- 新增 14 张透明 C 风格武器 PNG，保存在 `MoreWeaponsRegentExtend/images/vfx/unified/`。仅趁手兵器是开箱技能，不使用悬浮武器。
- 14 件武器均接入 `scenes/orbit/` 的原生 Godot 场景。旧武器不再使用旧 Spine 贴图；水晶小刀也改用自身贴图。
- 每个悬浮场景按 PNG 实际透明边界居中、调整显示大小和悬停区域，不修改生成图片的像素。保留头顶环绕位置、战斗图层、地图开关显隐、战斗结束清理和攻击复位。
- 攻击/使用场景也引用对应的 C 武器 PNG，保留原有位移、斩击、闪电、金币及粒子节奏。双翼使用同一张 PNG 的左右区域，保留独立展开动画。
- 居高临下、晶态、流血和王之枪四个状态图标采用透明 D 风格 PNG；大小图标路径均指向实际存在的文件。
- 固定 `RitsuLibAutoCopy=false`。NuGet 编译引用继续保留，显式部署本模组也不会复制本地 RitsuLib。

所有图片由内置 image_gen 逐件生成。提示词保存在本目录的 `art-unification/group-a-prompts.md`、`group-b-prompts.md`、`group-c-prompts.md` 和 `group-c-extra-prompts.md`；旧卡面与状态图片备份在 `.build/art-before-0.2.3/`。续作中新枪、子弹和状态图标的实际提示词分别保存于 `resume-gun-prompts.md`、`resume-bullet-prompts.md`、`resume-status-prompts.md`。未引入新第三方库。

[美术一览](art-unification/gallery.html)提供全部卡面、悬浮贴图与状态图标对照。

## RitsuLib 结论

游戏本地运行副本 `D:/steam/steamapps/common/Slay the Spire 2/mods/STS2-RitsuLib`（0.6.2）可以移除。保留工坊 `D:/steam/steamapps/workshop/content/2868840/3747602295`（0.6.5）和 NuGet 编译缓存。

核查的游戏版本为 0.111.0，工坊包提供对应兼容变体。本模组通过 NuGet 编译，移除游戏目录中的本地副本不会影响开发编译。按此前“仅修改本项目目录”的约束，本轮没有直接删除或移动游戏目录中的文件。关闭游戏后移除本地运行目录，并确认工坊版启用即可。

当前游戏会按较高版本处理重复 ID；仅凭重复安装不能解释两份都未加载。日志及禁用设置目录访问被拒绝，故没有确认该现象的直接原因，也没有修改 Steam 订阅或游戏禁用设置。详细证据与局限见 [依赖核查](dependency-ritsulib.md)。

## 游戏复验

1. 在卡牌库逐张查看 15 张卡面，确认没有旧图混入，构图完整。
2. 战斗内生成各武器，确认 C 贴图在储君头顶悬浮，尺寸与悬停范围合适。
3. 打出武器，确认攻击或使用贴图与悬浮造型一致，返回后位置正确；特别复验追踪之刃后的重斧、镰刀、长弓。
4. 战斗中打开/关闭地图，再结束战斗进入地图，确认武器不会挡住地图或残留。
5. 查看四个状态图标及悬停大图，确认 D 色块可辨识；居高临下描述仍正确显示两项 50%。
6. 仅保留工坊运行版 RitsuLib 时重新启动，确认依赖与本模组加载；再执行本项目构建，确认本地 RitsuLib 目录不会被重新创建。
