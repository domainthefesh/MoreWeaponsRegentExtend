# 0.2.2 地图遮挡与头顶环绕修复

根据玩家本轮验收，0.2.1的攻击/使用特效、卡牌结算、动画复位和能力文本均正常；本版处理环绕图层、战后残留与位置。

## 改动点

1. **战后主动清理。** 原先只依赖武器节点的TreeExiting，但游戏在胜利后显示地图时仍保留战斗房间与角色节点。水晶小刀沿用的原版浮剑同样纳入清理，只筛选本模组来源实例，保留原版君王剑的原有行为。现在RitsuLib全局AfterCombatEnd钩子主动移除全部模组环绕武器，CombatManager.CombatEnded事件补充失败等结束流程；清理时先隐藏，再停止动画、断开事件、移除登记并释放节点。
2. **地图打开与关闭。** 战斗中打开地图时隐藏环绕和对应悬浮提示，水晶小刀的原版浮剑也同步隐藏；关闭地图后恢复同一武器节点，避免重新生成或重复挂载。战斗初始化仍受IsStarting保护，不能把尚未开始的战斗误当结束。
3. **继承战斗图层。** 环绕节点固定ZIndex=0、ZAsRelative=true、TopLevel=false，沿用战斗场景的-10图层。前后深度使用角色子节点排序，贴近原版浮剑做法。
4. **恢复头顶轨道。** 使用NCreature.GetTopOfHitbox计算人物头顶，再向上偏移165；储君默认边界顶为-335，轨道中心为-500，纵向约-542到-458。新旧武器补偿各自局部初始位置，共用头顶轨道；角色位移与缩放后仍跟随。
5. **画风样稿和开发规划。** 单独保存干净线条的卡图/环绕风格对照样稿和后续路线图。正式游戏资源等待玩家选定风格后统一，开局选池、武器扩充、局外淬炼尚处设计阶段。

## 验证

- 使用实际游戏DLL、现有RitsuLib0.6.2及缓存Godot4.5.1 SDK完整编译，0错误、0警告。
- 真实Godot C#直接链接WeaponOrbitPresentation.cs，6/6回归通过：头顶高度、旧场景补偿、战斗层继承与前后排序、隐藏恢复不重建、父级位移旋转缩放、节点释放后的延迟回调安全。
- 已核对实际DLL中AfterCombatEnd、CombatEnded、IsStarting、NMapScreen.IsOpen及GetTopOfHitbox签名和调用时机。
- 本版未启动游戏实机复验；结束流程的最终表现仍需按下述步骤在游戏确认。

## 游戏复验

1. 用本版DLL/JSON/PCK进入战斗，生成旧武器、新增武器和水晶小刀，确认在人物头顶附近环绕。
2. 战斗中打开地图，确认没有武器和武器悬浮提示覆盖地图；关闭后武器恢复，数量不增加。
3. 赢得战斗，确认奖励页与随后地图页无环绕残留；进入下一战斗重新铸造后正常生成。
4. 另测战斗失败与退出战斗，确认无残留，打开地图后再关闭及连续打出武器不影响动画复位。
