# 0.6.1：淬炼验收修正与四种界面方案

日期：2026-10-07。0.6.0 的淬炼领取与各兵器强化已获作者实机确认；本轮根据验收反馈修复最后斩杀、调整五项效果，并提交四种界面方向。仅修改本工作区，继续使用 STS2-RitsuLib，没有为模组引入第三方库。

## 逐项改动

1. **君王之剑最后斩杀不再漏计。** 二阶奖励仍为每次斩杀使本局所有君王之剑基础伤害增加10。三个、两个、一个敌人的房间应分别累计增加30、20、10；群伤、多段、重复调度与重放不会重复统计同一死亡。原版不触发 Fatal 的死亡仍不发奖励。
2. **银河轨迹炮基础伤害100→50。** 保留十倍铸造加成、默认群攻、追踪之刃使整张牌额外打出一次、独立绑定充能、保留与消耗。
3. **晶刃碎裂生成的水晶小刀增加保留。** 原有消耗、零费与效果保持；回合末可以留下，打出后仍进入消耗堆。关键词来自原版，不额外增加自定义状态。
4. **海王三叉戟一阶奖励改为首次获得雷霆。** 每场战斗每张实体卡首次打出时，自身获得1层原版雷霆；同一张再打或额外重放不重复，真实复制独立计算。每次打出仍获得基础1层引雷，二阶海啸仍在伤害前施加。
5. **君王短匕二阶伤害翻倍→三倍。** 条件保持为目标没有攻击意图，或当前金币严格大于300；两个条件同时满足也只乘三。先按原有半额铸造形成伤害，再应用三倍乘数。斩杀金币奖励保持。
6. **君王之翼二阶居高临下100%→75%。** 减伤与增伤同时调整；未强化时仍为50%。二阶不再完全免伤，受到突破格挡伤害时仍减少一层。

卡面、能力提示和淬炼奖励说明同步更新中英文。模型标识不改名，保持现有本局保存与选择数据兼容。

## 最后击杀根因与修复

原来的结算依赖 `ForgeSingleton.AfterAttack` 战斗监听。原生 `Hook.IterateCombatHookListeners` 在战斗已结束／正在结束、且不处于初始化时停止枚举监听器。最后敌人死亡后，随后进入的 `AfterAttack` 因此不再调用单例，遗漏最后一次奖励；单例本身仍保持注册。

现在在伤害前保存 Fatal 资格快照，结算移动到原生 `Hook.AfterAttack` 的实际异步状态机初始入口，在原生结束门禁前读取真实 `AttackCommand.Results`。按死亡目标去重，并为每个命令保存已结算标记；没有放宽原生门禁。补丁由 Ritsu 的 `AsyncMethod` 注册，兼容先编译／内联异步包装器的路径；游戏接口不符时关键补丁明确失败，不静默漏奖。

旧综合夹具替换了活跃门禁，并保留默认的初始化状态，确实掩盖了最后死亡情况。本轮专项取消这两种替代，真实订阅 Ritsu 单例并令 `IsStarting=false`：修复前稳定得到10／20／20，修复后30；失败证据保留。

## 游戏内复验

1. 选择原版君王之剑并领取二阶：击杀两／三个敌人，最后敌人也应算一次；下一场新剑共享累计增长。
2. 炮未铸造时基础伤害50，铸造3后伤害80；追踪之刃仍对所有敌人额外打一遍。
3. 晶刃生成小刀后结束回合，确认留在手牌；打出后仍消耗。
4. 三叉戟一阶：每张首次获得1雷霆，再打同张不再获得；传承复制另有一次，剑术大师额外重放不重复。引雷每次仍为1。
5. 短匕二阶：金币300且目标攻击时正常，金币301或目标不攻击时三倍，两条件同时满足仍三倍。
6. 翼二阶：居高临下提示75%，未完全格挡时实际掉层；未领取二阶时50%。
